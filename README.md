# 上海地铁 2D 动态线路图

按**上海地铁官方时刻表**推演的 2D 动态线路图：给定任意时刻，图上显示全网每一条线路、
**每一个方向上正在运行的每一列车**——一条线路上同时显示多列车，因此可以直接看出
**发车间隔**与列车的分布。

## 在线访问

**<https://sunwebgo.github.io/shmetro-live/>**

打开后建议把右下角「日期类型」切到 **周一~周四**、时间轴拖到 **08:00**，可以看早高峰最密的发车间隔；
再切到 **周五** 并把时间拖到 **23:30**，能看到只有 1/7/8/9/10/13 号线仍在延时运营。

也可以直接用浏览器打开本地 `index.html`（纯静态，无需服务器、无需联网）。

## 功能

| 功能 | 说明 |
|---|---|
| 全网动态运行 | 21 条线路 / 24 个交路 / 418 座车站，逐列车按发车时刻表在图上运行 |
| 双向显示 | 每条线路按上与下行分别生成列车；车头上的白色三角指示行车方向 |
| 间隔可视化 | 同一条线路上多列车同时可见，高峰时列车间距明显变密 |
| 时间轴 | 拖动滑块到任意时刻；支持 1×／60×／300×／900× 推演与暂停 |
| 实时模式 | 「回到此刻」跟随真实时间（Asia/Shanghai） |
| 日期类型 | 自动／周一~周四／周五／周六／周日，切换官方的工作日、双休日、**周五周六延时运营**方案 |
| 线路详情 | 侧栏列出每条线当前的实际发车间隔、两方向在线列车数、首末班车时刻 |
| 车站到站 | 点击任意车站，显示各线路两方向的下一班列车、到站时刻与倒计时 |
| 地图交互 | 拖拽平移、滚轮缩放（围绕光标）、点击线路高亮、图例点击显隐线路 |

## 数据来源（全部为公开官方数据）

| 用途 | 来源 |
|---|---|
| 各站各方向**首末班车时间**（含周五/周六延时分钟增量、特定日期增量） | 上海地铁官方接口 `m.shmetro.com/interface/metromap/metromap.aspx?func=fltime&line=N`（备用域名 `marketing.cyberspaceit.cn`） |
| 各线路**列车间隔**（工作日 / 周五 / 双休日 / 延时运营，分时段、分区段） | 上海地铁官网「首末班车时刻表」页 `service.shmetro.com/hcskb/index.htm` 中的列车间隔表 |
| **线路走向、站点经纬度、线路颜色** | 高德地图地铁图接口 `map.amap.com/service/subway?srhdata=3100_drw_shanghai.json`；线路色以官方色值为准 |

抓取的原始响应保存在 `data/raw/`（`t.json` 为高德线路数据，`official/fltime_*.txt` 为官方首末班车，`hcskb_0.html` 为官方间隔表页面）。

## 推演口径

1. **首班车**：取官方该站该方向的首班车时刻；**末班车**取官方末班车时刻，
   周五/周六按官方 `last_time_desc` 的分钟增量顺延（如 1 号线 +88 分钟）。
2. **发车间隔**：完全按官方列车间隔表。表中「其余时段 x 分～y 分」按线性过渡处理
   （首班车后由慢变快、末班车前由快变慢）；周五/周六 22:30 后切换到延时运营间隔。
3. **站间运行时分**：官方未公布逐站运行时分，这里按
   `停车 35 秒 + 站间里程 / 线路旅行速度` 建模。默认旅行速度 48 km/h，
   高速线单独设定（16 号线 72、磁浮 200、市域机场线 100、17 号线 58、5 号线 52），
   使全程运行时分与公开量级一致（1 号线约 60 分、9 号线约 97 分、16 号线约 52 分）。
4. **多交路**：5 号线（奉贤新城主线 + 闵行开发区支线）、10 号线（虹桥火车站 + 航中路）、
   11 号线（嘉定北 + 花桥）分别作为独立交路运行，共线段列车叠加后，
   共线区间的实际间隔与官方表一致（例：5 号线莘庄～东川路叠加后约 2 分 30 秒）。
5. **4 号线**为环线，按内圈 / 外圈两个方向分别生成列车。

### 已知简化

- 延时运营期间官方只延长**部分区段**（如 7 号线祁华路～花木路），本图按该线路的延时
  幅度顺延全线末班车，未做区段截断。
- 未模拟 2 号线东延伸、16 号线大站车/直达车等特殊交路，也未模拟区间车提前折返。
- 磁浮线班次为参考公开信息估算（官方未提供接口）。
- 列车位置是按时刻表推演的**示意位置**，不是真实车辆定位数据。

## 目录结构

```
shmetro-live/
├─ index.html                 入口（直接双击打开）
├─ css/style.css
├─ js/sim.js                  仿真内核：发车表生成、时刻→位置换算、到站推算
├─ js/app.js                  Canvas 渲染、交互、面板
├─ data/metro-data.js         前端数据（由构建脚本生成，约 40 KB）
├─ data/preview_*.png         四个时刻的静态预览图
├─ data/raw/                  抓取到的官方/高德原始数据
└─ tools/
   ├─ build_data.py           生成 data/metro-data.js（含行车间隔表定义）
   ├─ test_sim.js             仿真内核无头校验
   ├─ test_ui.js              前端脚本无头校验（Node + DOM 桩）
   ├─ snapshot.js             导出指定时刻的绘制数据（复用 sim.js）
   └─ render_png.py           把快照渲染成 PNG
```

## 重新构建 / 校验

```powershell
$py   = "<python>"        # 需含标准库即可
$node = "<node>"

# 1) 由原始数据重新生成前端数据
& $py   tools/build_data.py          # -> data/metro-data.js + data/build-report.txt

# 2) 仿真内核校验（间隔取值、发车表、在线列车、到站推算、环线）
& $node tools/test_sim.js

# 3) 前端脚本校验（渲染、面板、点击/缩放/控件、24 小时全时段绘制）
& $node tools/test_ui.js

# 4) 生成静态预览图
& $node tools/snapshot.js mon_thu 1 08:00 data/snap.json 1600 1000
& $py   tools/render_png.py data/snap.json data/preview_0800_weekday.png
```

`tools/build_data.py` 顶部的 `HEADWAY_SPEC` 是人工整理自官方间隔表的行车间隔定义，
每条都附有官方原文（如「工作日 早高峰2分30秒/平峰5分/晚高峰3分/其余4~9分」），
可按需修改后重新构建。

## 部署（GitHub Pages）

仓库：<https://github.com/sunwebgo/shmetro-live>

采用 GitHub Pages **分支部署**：源为 `main` 分支根目录（`build_type: legacy`），没有构建步骤，
推送到 `main` 后约 1 分钟自动发布到 <https://sunwebgo.github.io/shmetro-live/>。

因为全部是静态文件（HTML + CSS + JS + 数据），除 GitHub Pages 外，任意静态托管
（本地直接打开、Nginx、Vercel、对象存储等）都能原样运行。
